# RocketCloud, Coolify и перенос

## Подготовка

Нужен Linux-сервер с Docker, постоянным диском, доступом к приватному GitHub-репозиторию и доменом. Стартовый ориентир для проверки: 2 vCPU и 4 ГБ RAM; это не гарантия для полного объёма нагрузки. OR-Tools ограничен двумя потоками и 30 секундами решателя, worker ограничен 2 ГБ. На этапе сборки нужно место для Node/Python-образов и пакетов.

Секреты задаются через панель или локальный `.env`, который исключён из git: пароль PostgreSQL, четыре пароля пользователей. DB-пароль в этом Compose используйте буквенно-цифровой, потому что он входит в URL. `ALLOWED_HOSTS`: фактический домен без схемы/порта, плюс `localhost,127.0.0.1` для проверок. `SECURE_COOKIES=true`.

## Coolify

1. Добавьте приложение из приватного `eltkk/college-scheduler` через GitHub App или read-only deploy key, ветка `main`.
2. Выберите сборку Docker Compose, файл `/compose.yaml`, рабочий каталог корня репозитория.
3. Задайте переменные из `.env.example`, заменив все секреты. В панели `BOOTSTRAP_USERS` задаётся как JSON-массив без внешних shell-кавычек.
4. Назначьте публичный HTTPS-домен сервису `web`, внутренний порт `8000`. `db` и `worker` не получают публичных доменов. В интерфейсе Compose Coolify при необходимости URL маршрутизации указывается как `https://schedule.example.org:8000`; внутренний порт не означает публичный доступ на 8000.
5. Запустите развёртывание. Проверьте логи миграции/инициализации, здоровье `web`/`db`, работу `worker` и вход четырёх пользователей.
6. Убедитесь, что тома `postgres` и `uploads` постоянные и не удаляются при повторном deploy. Выполните повторный deploy и проверьте сохранённую запись/оригинальный XLSX.

Имена полей панели могут отличаться по версии Coolify. Официальные справочники: [Docker Compose](https://coolify.io/docs/applications/builds/docker-compose), [Deploy keys](https://coolify.io/docs/applications/sources/deploy-keys).

Поддержка HTTP для локальной разработки есть только в `compose.local.yaml`; в Coolify он не используется. Не включайте автоматический deploy непроверенного изменения перед сдачей.

## Копии и восстановление

Скрипты рассчитаны на запуск из клона проекта с тем же Compose и `.env`. Для ресурсов, имена/compose которых изменяет Coolify, используйте фактический compose-каталог ресурса на сервере или настройте эквивалентные команды; не создавайте второе приложение из другого каталога ради бэкапа.

```sh
./deploy/backup.sh /secure/backup-directory
```

Скрипт кратко останавливает web/worker, создаёт `pg_dump -Fc` и архив оригинальных XLSX, затем запускает приложение. Остановка исключает рассогласование метаданных документов и файлов. Уведомляйте составителей о кратком обслуживании. При ошибке сначала проверьте целостность полученных файлов; не считайте пустой дамп успешной копией.

Копии с того же сервера нужно регулярно переносить на отдельное защищённое хранилище. Скрипт не подключён к расписанию автоматически: перед эксплуатацией настройте ежедневный запуск и контроль ошибки через доступный серверный планировщик. Хранение копий в git запрещено.

Проверяйте восстановление на отдельном тестовом размещении. Команда заменяет текущую БД и файлы:

```sh
./deploy/restore.sh /secure/backup-directory/20261006T120000Z --replace-current
```

Перед восстановлением сделайте свежую копию текущего состояния. При ошибке восстановления приложение остаётся остановленным; устраните причину и повторите. После восстановления проверьте четыре логина, нужную версию, расписание и скачивание исходного Excel. Не выполняйте `docker compose down -v` на рабочем приложении.

## Перенос

Сохраните commit приложения, Compose, конфигурацию/секреты отдельно от исходников, базу и оригинальные XLSX. На новом сервере соберите тот же commit, создайте пустые тома, запустите PostgreSQL и восстановите копию. Запустите web/worker, настройте HTTPS и ALLOWED_HOSTS, проверьте работу. Только после проверки переключите DNS и отключите старое размещение. Краткая остановка старого приложения нужна для окончательной копии, иначе поздние правки потеряются.

## Что не выполнено без доступа к серверу

Не подтверждены фактическая конфигурация RocketCloud, домен/сертификат, постоянство томов именно в вашей панели, серверный график копий и восстановление на целевом хостинге. Наличие Dockerfile не означает, что размещение уже выполнено.
