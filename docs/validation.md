# Проверка первой версии

## Автоматические проверки

Backend: конфликты преподавателя/группы/помещения, общая теория, параллельные подгруппы, дневной предел родителя, вместимость клинической базы, нечётные часы и два одночасовых занятия в паре, длинные блоки, закрепления, праздники, доступность, переходы, безопасный Excel и объединения.

API: четыре равноправных логина, CSRF/выход, лимит неверного входа, устаревшие правки, атомарный откат, запрет удаления используемого ресурса, асинхронная генерация/просмотр/применение, отклонение устаревшего результата, обмен двух занятий, повторный импорт, сохранение самостоятельной работы, блокировка ошибок часов и сверка нагрузки с КУГ.

Отдельный тест с PostgreSQL запускает две параллельные транзакции на одной версии и требует ровно одну успешную запись. SQLite этот тест пропускает. CI дополнительно проверяет соответствие миграции модели, frontend build и контейнерный запуск/копию/восстановление.

Проверка исходных двух КУГ выполнялась локально: распознаны все 7 листов, объединённые недельные колонки и координаты исходных часов. Реальные файлы не включены в CI. Это проверка формата, не подтверждение календарной привязки или преподавательских назначений.

## Браузер

`frontend/tests/smoke.spec.ts` проверяет вход, генерацию/применение, видимость всех занятий, отчёт часов, отклонение ручного пересечения без записи, сохранение справочника, открытие настроек/импорта/истории и скачивание Excel. Запускается на отдельном учебном размещении с переменными `E2E_LOGIN`, `E2E_PASSWORD` и при необходимости `E2E_BASE_URL`; реальные рабочие данные использовать нельзя. В CI учебные данные и секреты создаются отдельно.

```sh
cd frontend
npx playwright install chromium
npm run test:e2e
```

## Перед сдачей заказчику

- Получить реальную нагрузку и число групп/подгрупп/преподавателей.
- Подтвердить звонки, учебные дни, календарные даты КУГ, потоки, практику и ограничения мест.
- Сопоставить недельные часы КУГ и нагрузку, уточнить расхождения.
- Сгенерировать несколько реальных недель, включая общую теорию, практику и неделю с особыми режимами; сравнить точные часы по каждой группе/предмету/виду.
- Замерить время и память на полном составе колледжа, проверить диагностику невыполнимого плана.
- Проверить ручные правки и конфликт двух составителей с разных компьютеров.
- Сверить Excel с требуемым оформлением колледжа, печать и неполные/блочные занятия.
- На RocketCloud проверить HTTPS, четыре входа, повторный deploy без потери данных, резервную копию и восстановление.

Приложение не считается сданным колледжу только на основании учебного примера или успешного build.


## Зафиксированные локальные результаты

После исправлений: 35 backend/API/импортных тестов прошли, PostgreSQL-тест пропущен локально и запускается в CI. Сборка TypeScript/Vite прошла. Chromium-проверка основного пользовательского сценария прошла, ошибок JavaScript не обнаружено.

Синтетический пример: 20 групп по 25 студентов, 40 преподавателей, 20 отдельных помещений, 100 недельных потребностей по 6 часов, всего 600 часов и 300 занятий. Генератор нашёл optimal за 12,44 сек. вместе с построением и независимой проверкой на текущей среде. Это относительно простой сценарий с закреплёнными за группами помещениями, он не является замером реального колледжа или гарантией времени на RocketCloud. Воспроизведение: `python -m app.benchmark`.
