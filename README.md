# Расписание колледжа

Веб-приложение для автоматического составления недельного расписания по подтверждённым часам КУГ и преподавательской нагрузке. Python/FastAPI, PostgreSQL, OR-Tools, React/TypeScript. Размещение: Docker Compose, в том числе RocketCloud + Coolify.

## Что работает

- Четыре отдельных аккаунта с одинаковыми правами, закрытый вход, защищённые сессии.
- Группы и подгруппы, потоки, преподаватели, дисциплины, кабинеты и клинические базы.
- Учебные дни, звонки, праздники, доступность ресурсов, дневные/недельные пределы и переход между корпусами.
- Загрузка КУГ XLSX с объединёнными неделями, предварительной проверкой, привязкой реальных дат, групп, преподавателей и помещений. Самостоятельная работа сохраняется в плане без назначения пар. Нечётные часы не округляются.
- Семестровая нагрузка DOCX: исходные таблицы, проверка назначений и сложных часов, подтверждение новых справочников, отдельные часы периода и связь с недельным КУГ.
- Импорт недельной нагрузки XLSX через сопоставление колонок. Повторные назначения сверяются с часами КУГ; несовпадение отклоняет весь импорт.
- Автоматическая генерация отдельным процессом: общая теория, практика отдельных групп, блоки занятий, ограничения преподавателей/групп/помещений и вместимости. Результат применяется только после просмотра, при актуальной исходной версии.
- Недельная сетка, ручное редактирование, закрепление, атомарный обмен двух занятий. Сервер запрещает конфликты.
- Отчёт план/размещено/остаток, Excel с объединёнными общими занятиями и листом часов, история и восстановление состояния.
- Docker, миграции, резервное копирование базы и оригинальных файлов, инструкция переноса, проверки в GitHub Actions.

## Границы текущей версии

Реальные четыре документа нагрузки Word и два КУГ проверены локально. Структура поддерживается приложением; назначения, группы и календарь ещё требуют подтверждения колледжа. Реальные документы и персональные данные в репозиторий не включены. У КУГ есть противоречия в заголовках набора/курса/базы: привязку подтверждает составитель. Начальные звонки являются примером, генерация закрыта до их подтверждения.

Поддерживаются XLSX КУГ с шапкой «Индекс» и недельными колонками, DOCX с семестровыми таблицами нагрузки и недельная нагрузка XLSX с настраиваемыми колонками на первом листе. Формулы читаются по сохранённым значениям; приложение не пересчитывает Excel. Непрочитанные, отрицательные или дробные часы блокируют подтверждение соответствующей недели. Фотографии расписания служат образцом структуры, не источником нагрузки.

Генератор полностью размещает выбранную подтверждённую недельную нагрузку либо сообщает об отсутствии решения/лимите времени. Оптимизация предпочитает ранние интервалы; пожелания о равномерности, минимуме окон или строгих первых/последних парах пока не являются отдельными правилами. Максимум 50 000 кандидатных назначений защищает процесс от слишком широких входных данных. Производительность на полном колледже нужно измерить после получения нагрузки.

При выборе части групп в генерацию включается только нагрузка, все участники которой выбраны. Для общей лекции потока выберите все его группы. Для нескольких преподавателей указывается режим: один из списка или все вместе на каждом занятии. Несколько помещений означают разрешённые альтернативы. Семестровые пределы проверяются для связанных недельных строк; несвязанные соответствующие строки отмечаются предупреждением.

## Запуск через Docker

```sh
cp .env.example .env
# Замените пароль PostgreSQL, все четыре пароля и ALLOWED_HOSTS.
docker compose -f compose.yaml -f compose.local.yaml up --build -d
```

Локально: http://localhost:8000. `compose.local.yaml` включает доступ только с этого компьютера и cookies для HTTP. Для публичного размещения используйте основной `compose.yaml` и HTTPS через Coolify. База не публикует порт наружу.

При первом старте выполняются миграции и создаются четыре аккаунта из `BOOTSTRAP_USERS`. Примерные пароли `REPLACE_*` не принимаются. При последующих запусках аккаунты не перезаписываются. Изменение переменной не меняет уже созданный пароль:

```sh
docker compose exec web python -m app.cli password --login editor1
```

Для отдельного пустого тестового размещения можно заполнить учебный пример **до** инициализации рабочего состояния:

```sh
docker compose build
docker compose up -d --wait db
docker compose run --rm --no-deps web alembic upgrade head
docker compose run --rm --no-deps web python -m app.cli init --demo
docker compose -f compose.yaml -f compose.local.yaml up -d
```

Команда не заменяет уже существующие данные. Пример не содержит данных колледжа.

## Разработка без Docker

Python 3.12+, Node 24, PostgreSQL 17. Настройте `DATABASE_URL`, `ALLOWED_HOSTS`, `SECURE_COOKIES` и четыре аккаунта через локальный `.env`, затем:

```sh
python -m venv .venv
. .venv/bin/activate
pip install -r requirements.lock
alembic upgrade head
python -m app.cli init
uvicorn app.main:app --reload --port 8000
# В другом терминале с тем же окружением:
python -m app.worker
# Интерфейс в третьем терминале:
cd frontend
npm ci
npm run dev
```

Vite проксирует `/api` на порт 8000. Для локального HTTP выставите `SECURE_COOKIES=false`.

## Проверки

```sh
pytest -q
cd frontend && npm run build
```

Тесты создают отдельную временную SQLite-базу и игнорируют рабочий `DATABASE_URL`. PostgreSQL-проверка блокировок запускается с `TEST_DATABASE_URL`, имя базы должно быть `college_scheduler_test`. В GitHub Actions используются настоящий PostgreSQL, проверка миграций, сборка интерфейса, Docker-старта и восстановления резервной копии. Браузерная проверка описана в [docs/validation.md](docs/validation.md).
